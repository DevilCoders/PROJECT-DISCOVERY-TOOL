# SQL and Migration Intelligence

The initial SQL analyzer statically inventories common CREATE TABLE/VIEW/INDEX/PROCEDURE/FUNCTION/TRIGGER declarations and REFERENCES clauses, with plain, `"quoted"`, `` `backtick` `` (MySQL) and `[bracket]` (SQL Server) identifiers and PostgreSQL's `UNLOGGED`, `MATERIALIZED` and `CONCURRENTLY` forms. It also flags potentially destructive DROP TABLE, DROP DATABASE, TRUNCATE and ALTER TABLE DROP COLUMN patterns as INFERRED findings, except a `DROP TABLE` of a table the file creates again (the guards in mysqldump and pg_dump output) and statements in a migration's rollback section (`-- +goose Down`, `-- migrate:down`). The migration analyzer applies the same rule to rollback code (Alembic `downgrade()`, Rails `def down`, knex and TypeORM `down`, Laravel `down()`, EF Core `Down()`, Liquibase `<rollback>`).

It does not connect to a database, execute SQL, resolve dialect-specific semantics, or claim that a source schema matches a live database. The initial patterns are lexical and require review; advanced parsing, ORM mappings, migration framework state, rollback analysis, NoSQL models and cross-dialect schema diffing remain future work.
